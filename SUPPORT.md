## Bugs and feature requests

Use GitHub Issues:

<https://github.com/abdou-da0wew/REEO/issues>

> **Repository status:** Issues may currently be disabled while the maintainer finishes GitHub setup. If the link returns “not found” or issues are unavailable, open a pull request with a clear description or contact [@abdou-da0wew](https://github.com/abdou-da0wew) through GitHub. Do not post security details publicly.

Include:

- REEO version (`window.reeo.version` or the deployment URL/commit),
- platform, browser/OS, and viewport size,
- language (`en`, `ar`, `arz`),
- steps to reproduce from a fresh board,
- expected vs. actual behavior,
- exported `.board` for circuit bugs (remove anything private),
- console/network errors and a screenshot for visual issues.

Do not attach secrets, personal data, or boards you cannot share.

## Questions and ideas

There is no hosted discussion forum. Use an issue for a concrete bug/enhancement; for a large design proposal, explain the user problem and how it fits the existing REEO interface before writing code.

## Security

Report privately via [SECURITY.md](SECURITY.md). Never disclose a vulnerability in an issue, pull request, or social post before maintainers have had a chance to respond.

## Data loss

Boards are stored locally in your browser/app profile. There is no server backup. Export `.board` files regularly. The maintainers cannot recover data that a browser, OS, or user cleared.

See [Troubleshooting → Boards and storage](docs/TROUBLESHOOTING.md#boards-and-storage) for recovery options.

## Contributing

Pull requests are welcome. Read [CONTRIBUTING.md](CONTRIBUTING.md) first. Do not expect a new framework rewrite or a replacement visual identity to be accepted; REEO deliberately preserves its original interface.
